# ZHANAR Massage Academy для браузера

Веб-кабинет использует тот же Supabase Auth, PostgreSQL и Storage, что и iOS. Курс появляется в каталоге после публикации. Доступ к платным урокам определяется действующей покупкой в verified_purchases. Покупка и восстановление транзакции выполняются в iOS через StoreKit. В браузере ученик входит тем же аккаунтом, открывает библиотеку и продолжает занятия.

## Локальный запуск

Из каталога web на Node.js 22.13 или новее выполните команды ниже. На новом компьютере сначала скопируйте .env.example в .env и укажите адрес проекта и его публичный ключ sb_publishable_.

```sh
npm ci
npm run dev
```

Откройте http://localhost:4173. Для проверки выполните npm test, npm run lint и npm run typecheck. Выполните npm run build и npm start для запуска собранной версии. Для работоспособности аккаунтов и материалов требуется активная база и сетевое соединение.

## Передача и развёртывание

1. Подготовьте домен с HTTPS. В Supabase Authentication → URL Configuration добавьте точные разрешённые адреса https://ДОМЕН/auth/callback и http://localhost:4173/auth/callback для разработки. Сохраните существующие адреса iOS. Настройте доставку писем школы. Пользователь должен открыть ссылку из письма в том же браузере, где запросил её.
2. Передайте процессу переменные NODE_ENV=production, APP_ORIGIN=https://ДОМЕН, SUPABASE_URL и SUPABASE_PUBLISHABLE_KEY. SUPABASE_PHONE_ENABLED=true включает вход по SMS после подключения SMS-провайдера. SUPPORT_URL, PRIVACY_URL, TERMS_URL и APP_STORE_URL принимают утверждённые школой HTTPS-ссылки.
3. Соберите в каталоге web командой npm run build, передайте dist на сервер и запустите node dist/server.mjs с указанным окружением. Альтернатива для контейнера — docker build -t zhanar-web . и docker run --env-file /путь/production.env -p 127.0.0.1:4173:4173 zhanar-web. Для контейнера задайте HOST=0.0.0.0. Проксируйте домен на порт 4173. При использовании TRUSTED_PROXY_IP прокси обязан заменять X-Real-IP адресом клиента. Для нескольких экземпляров используйте общее ограничение частоты запросов на прокси.
4. Проверьте подтверждение почты, смену пароля и повторный вход тестового пользователя. На тестовом проекте проверьте загрузку обложки, видео и публикацию. Сверьте библиотеку и прогресс с iPhone под тем же аккаунтом. Приватные видео открываются по временным ссылкам. Пароли обслуживает Supabase, токены сеанса хранятся в HttpOnly cookie. Ключ service_role веб-серверу не нужен.

## Управление курсами

В кабинете администратора откройте «Управление академией». Создайте черновик с идентификатором продукта App Store, добавьте разделы и уроки, заполните переводы, загрузите обложку и видео. База проверяет материалы перед публикацией. Размер обложки до 5 МБ, видео до 50 МБ. Роль назначает владелец проекта в существующей таблице course_admins. [Права администратора и массовый импорт](../supabase/COURSE_IMPORT.md). При подключении отдельного тестового проекта примените миграции и настройте Edge Functions согласно [инструкции Supabase](../supabase/README.md).

Тесты в test используют изолированные ответы сервисов. Они проверяют решения сервера о доступе, формат запросов, авторизацию и ошибки. Для приёмки оплаты нужен тестовый товар App Store и покупка через iOS.

Автоматический сценарий Chrome запускается командой `npm run test:browser`. Он использует временный локальный сервер с тестовыми данными и проверяет мобильный и настольный интерфейсы. На других системах задайте CHROME_PATH с путём к Chrome или Chromium.
